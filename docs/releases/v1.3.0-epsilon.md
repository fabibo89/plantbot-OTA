# PlantBot Firmware v1.3.0-epsilon

Änderungen seit **[v1.3.0-delta](v1.3.0-delta.md)**. Pre-release-Kanal (`Pre-Releases` in `/config`).

---

## Highlights

- **Gieß-Abbruch klarer gemeldet:** Überschreitet ein Job die max. Gießdauer, kommt im MQTT-ACK jetzt `max_duration_exceeded` (neben Tank leer / manuell abgebrochen). Server und Monitoring können das anzeigen.
- **Ventil-MQTT stimmt mit HA überein:** Ventil-State ist die Pump×Ventil-Matrix aus dem aktiven Gießjob — nicht mehr nur der PCA-Kanal. Mehrpumpen-Setups melden wieder die richtigen Entities.
- **MiFlora-Batterie wieder da:** Auslesen über die richtige Charakteristik (`0x1a02`), sparsames Polling, kein `bat: 0` mehr wenn der Wert noch unbekannt ist. Weniger Heap-Druck durch wiederverwendete NimBLE-Clients.
- **Wasserstand robuster:** Unmögliche Oberflächen-Messungen (über Tanktiefe + Margin) werden verworfen; Distanzsensoren clampen und soft-failen, wenn Hardware fehlt.
- **TOF-Diagnose:** Rohabstand als `tof_mm` im Sensor-JSON / Status — unabhängig von Tanktiefe-Filter.
- **Config-Portal-Grund auf dem Display:** Warum der Portal-Modus aufging (WiFi-Timeout / Button / Web).
- **System-Seite am Gerät:** Unter `/system` Heap, SPIFFS, Chip-Temp, WLAN, Firmware/Uptime — plus API `/api/system`.

## Änderungen im Detail



### Gießen / MQTT

- Job-Ende „Zeitüberschreitung“ → ACK `error: max_duration_exceeded`
- Weiterhin: „Tank leer“ → `water_level_below_minimum`, „Abgebrochen“ → `user_aborted`
- Server/Frontend: Fehlercodes in Watering-Logs und Live-Status übersetzen (begleitendes Server-Update)
- `publishValves()`: State aus aktivem Job (Pumpe × Ventil), nicht aus PCA-Kanal allein — HA-Entities mit mehreren Pumpen bleiben konsistent



### MiFlora (Bluetooth)

- Batterie + Firmware-Char UUID `00001a02-…` (nicht Standard-GATT Battery Service)
- Erster erfolgreicher Read setzt `batteryKnown`; danach alle N Polls (`BATTERY_INTERVAL`)
- Sensor-JSON: `bat` nur wenn bekannt
- Persistente NimBLE-Clients pro Sensor (weniger Heap-Drift), NimBLE **2.5.1**



### Wasserstand / Distanz

- Surface > Tanktiefe + 10 cm → verwerfen (Ultraschall und TOF)
- Init/Clamp für Distanzsensoren bei fehlender oder unplausibler Hardware
- Optional im Payload: `tof_mm` (mm), wenn VL53L1X verfügbar — auch wenn `water_surface_cm` / `water_level` fehlen



### WiFi / Display

- Config-Portal: Display-Zeile „Grund: …“ (`WiFi Timeout` / `Button` / `Web`)



### Web-UI

- Neue Seite `/system` (Auto-Refresh ~5 s) + `GET /api/system` (Heap, SPIFFS, Chip, WLAN, BME, MQTT, …)
- Startseite: Link **System**
- Route in Firmware + SPIFFS (`Updater/system.html`)



### Home Assistant / Server

- ACK-Fehlercodes für Timeout/Abort auswerten (Monitoring / Watering-Logs)
- Ventil-Entities: MQTT-State folgt der Job-Matrix (Pump×Ventil); nach Update kurz Gießjob starten und Entity-State prüfen
- MiFlora: Template-Key `bat` (Alias `batt`/`battery`); fehlende Batterie ≠ 0 %
- Empfohlen: HA-Integration nach Firmware-Update neu laden

## Upgrade-Checkliste

1. Firmware `v1.3.0-epsilon` per OTA (Beta-Schalter) oder USB flashen
2. SPIFFS: sollte mit OTA kommen; sonst manuell:

```bash
IP=192.168.10.99   # IP deines PlantBots

for f in Updater/*; do
  curl -sS -X POST "http://$IP/upload" \
    -F "upload_dir=Updater" \
    -F "upload_data=@$f"
  echo "  $f"
done
```

1. `/config`: Pre-Releases aktiv; Tanktiefe / `useTank` prüfen
2. Test: Startseite → **System** (Heap/SPIFFS/Temp)
3. Test: MiFlora → `bat` in MQTT/`/status` nach ein paar Polls
4. Test: Gießen über Max.-Dauer → ACK/Log `max_duration_exceeded`
5. Test: Gießjob mit Pumpe/Ventil → HA-Ventil-Entity schaltet mit (besonders Mehrpumpen)
6. Optional: bei TOF-Problemen `tof_mm` im Status prüfen
7. HA neu laden

## Bekannte Hinweise

- `tof_mm: 0` heißt oft „noch kein gültiger Read“ / I2C-Timeout — nicht zwingend tote Hardware; Sensor nicht unter Spannung abziehen.
- Chip-Temperatur (`chip_temp_c`) ist die interne ESP-Schätzung, nicht Raumtemperatur.
- Config-Parameter `version` bleibt über `/config` absichtlich read-only (wird von OTA gesetzt).
- Companion: Server-Frontend-Labels für die neuen Error-Codes mitdeployen, sonst sieht man nur den Rohcode.
