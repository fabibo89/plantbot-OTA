# PlantBot Firmware v1.3.0-beta

**Pre-release / Beta** — GitHub als Pre-release veröffentlichen.  
**Basis:** Änderungen seit **[v1.3.0-alpha](v1.3.0-alpha.md)** (24. August 2026).  
**OTA-Kanal:** `pre-release:v1.3.0-beta` in `version.txt` (Checkbox „Pre-Releases (Beta)“ in `/config` aktiv).  
**Home Assistant:** empfohlen **[plantbot-HA v1.2.10-beta](https://github.com/fabibo89/plantbot-HA/releases)** (MQTT-Status-Metriken, Gieß-Event).

---

## Highlights

- **MQTT-Status erweitert:** `flow`, `last_volume_ml`, `water_runtime`, `watering` und `last_reset_reason` werden regelmäßig über `plantbot/{ip}/status` gesendet (wie früher HTTP `/status`, jetzt für HA per MQTT).
- **MQTT-ACK erweitert:** Nach Server-Gießjobs (`job_id > 0`) enthält `plantbot/{ip}/ack` zusätzlich `plant_name`, `pump_number` und `valve_number` — Grundlage für HA-Automationen (Event `plantbot_watering_finished`).
- **OTA-Status JSON bereinigt:** `include_prereleases` erscheint nicht mehr im öffentlichen Status-JSON (Arduino-libs).

---

## Änderungen im Detail

### MQTT / Home Assistant

**Topic `…/status`** (zusätzlich zu `firmware_version`, `wifi_rssi`, `free_heap`, `uptime_seconds`):

| Feld | Bedeutung |
|------|-----------|
| `flow` | Aktueller Durchfluss (Wasser-Flowmeter) |
| `last_volume_ml` | Letztes gemessenes Volumen (ml) |
| `water_runtime` | Laufzeit der letzten Bewässerung (s) |
| `watering` | `true`, solange ein Gießjob läuft |
| `last_reset_reason` | ESP-Reset-Grund seit letztem Boot |

**Topic `…/ack`** (bei Job-Ende, nur `job_id > 0`):

| Feld | Bedeutung |
|------|-----------|
| `plant_name` | Pflanzenname aus dem Server-Water-Command |
| `pump_number` / `valve_number` | Zugeordnete Hardware |

Während des Gießens kommen Live-Werte weiter über `…/logs`; im Idle ca. 1×/s über `…/status` (bzw. bei `commands/status_request`).

### Arduino-libs

- `GithubUpdater`: internes Feld `include_prereleases` nicht mehr im Status-JSON (kein Verhalten für OTA-Kanal geändert).

## Zugehörige Home Assistant (v1.2.10-beta)

Diese Firmware-Version passt zu **plantbot-HA ≥ 1.2.10-beta**:

- MQTT-Metriken **Flow**, **Volume**, **Wasser Runtime**, **Letzter Reset Grund** aus `…/status`
- Event **`plantbot_watering_finished`** (nur Server-Betrieb) mit `plant_name`, `job_id`, Mengen, Status
- Server-Refresh behält MQTT-Livedaten; Sensor-Fallback über Server `last_value`

→ **[plantbot-HA v1.2.10-beta](https://github.com/fabibo89/plantbot-HA/releases)**

## Upgrade von v1.3.0-alpha

1. In `/config` „Pre-Releases (Beta)“ aktiv lassen.
2. Firmware **v1.3.0-beta** per OTA oder USB flashen.
3. **SPIFFS:** Wenn `spiffs-data.zip` von **v1.3.0-alpha** bereits auf der Station liegt, ist **kein erneuter SPIFFS-Upload** nötig (nur Firmware geändert). Sonst wie in [v1.3.0-alpha](v1.3.0-alpha.md) `Updater/*` nachladen.
4. HA-Integration auf **v1.2.10-beta** aktualisieren und **neu laden**.
5. Kurz prüfen: Station-Sensoren (Flow/Volume/Runtime/Reset), ein Server-Gießjob → HA-Event / ACK mit `plant_name`.

---

## Bekannte Hinweise

- Direkte Ventil-Befehle aus HA (`job_id < 0`) senden **kein** ACK und lösen **kein** `plantbot_watering_finished` aus.
- `plant_name` im ACK stammt vom Server-Job; ohne Server nur Pump/Ventil im ACK.
- Alpha-Hinweise (SPIFFS-Workaround `/config`, Spülmenge 50 ml, …) gelten weiter — siehe [v1.3.0-alpha](v1.3.0-alpha.md).
