# PlantBot Firmware v1.3.0-delta

Änderungen seit **[v1.3.0-gamma](v1.3.0-gamma.md)**. Pre-release-Kanal (`Pre-Releases` in `/config`).  
**HA:** aktuelle Integration (schlanker Status, nested Logs, `/restart`).

**Wichtig:** Web-UI für Delta **noch manuell** nachladen (curl in den Details). Ab Delta zieht OTA die UI bei späteren Updates automatisch mit.

---

## Highlights

- **Tank in den Einstellungen:** Unter PlantBot → Tank kannst du den Tank ein-/ausschalten. Nur wenn aktiv: Tanktiefe und Mindestfüllstand einstellen. Aus = keine Füllstands-Prüfung / kein Wasserstand aus Ultraschall/TOF.
- **Ultraschall-Wasserstand wieder zuverlässig:** Sensor-Erkennung beim Start war fehlerhaft und hat den Ultraschall oft dauerhaft abgeschaltet — behoben.
- **Modbus-Seite am Gerät:** Unter `/modbus` (auch von der Startseite) Sensoren anzeigen, Bus scannen und Slave-Adressen umschreiben — ohne Laptop-curl.
- **Neustart klarer:** Auf der Startseite gibt’s einen Neustart-Button; Display zeigt „Neustart…“ und bleibt darauf, bis der PlantBot neu startet. Endpoint heißt jetzt `/restart` (statt `/HA/reset`).
- **OTA aktualisiert künftig auch die Web-Oberfläche:** bei späteren Updates UI-Dateien mit (`config.json` bleibt). Diesmal: manuell, siehe Details.
- **Einstellungen aufgeräumt:** Alter „Legacy HTTP“-Server (PHP) ist raus — MQTT ist der Weg.
- **Live-Gießdaten übersichtlicher:** Während Düngen/Spülen/Gießen kommen nur die gerade relevanten Werte (Wasser oder Dünger), nicht alles vermischt.

## Änderungen im Detail



### Einstellungen & Web-UI

- `/config`: Sektion **Tank** mit Checkbox `useTank`; Felder Tiefe / Mindestfüllstand ein-/ausblendbar
- Legacy-Parameter `server` und Config-Gruppe „Legacy HTTP“ entfernt
- Startseite: Link **Modbus**, Button **Neustart** (ruft `/restart`)
- Neue Seite `/modbus` + APIs `/api/modbus`, `/api/modbus/scan`, `/api/modbus/change` (spezifische Routen vor dem Prefix)
- Entfernte Alt-Endpunkte: `/HA/valve/open|close`, `/Pump`, `/setVersion`, alte `/Modbus*` ohne UI
- `config.json`: fehlende/null-Parameter werden nicht mehr als Text `"null"` geladen (Puffer-Overflow bei neuen Checkboxen)



### Sensorik

- `Ultraschall::initialise`: `available` vor dem ersten `update()` setzen; Distanz `<= 0` → nicht verfügbar
- Wasserstand-Logik: ohne Tank (`useTank` aus / Legacy Tiefe 0) keine Fill-Berechnung und kein Mindeststand-Block



### Neustart & WLAN

- `GET /restart`: Antwort senden, Display-Text, Flag; `ESP.restart()` erst im `loop` (~800 ms)
- `printMessage(..., time=0)` hält die Anzeige (`showingMessage`); Pump-/Sensor-UI überschreibt nicht mehr
- `WifiCtrl::checkConnection`: kein `WiFi.disconnect()`-Hammer, non-blocking Retry alle 5 s, Restart erst nach längerer Offline-Zeit



### OTA / SPIFFS

- `GithubUpdater`: vor `firmware.bin` best-effort Download der UI-Dateien vom Tag  
  `raw.githubusercontent.com/…/plantbot-OTA/<tag>/spiffs-data/…`
- Dateiliste aus `spiffs-data/manifest.json` (Fallback-Liste in der Firmware); `config.json` wird nie überschrieben
- Auto-OTA nutzt den **Git-Tree am Tag**, nicht die Release-Zip
- **Delta selbst:** Auto-SPIFFS greift erst *nach* Installation dieser Firmware → Web-UI für Delta **einmal manuell** nachladen:

```bash
IP=192.168.10.179   # IP deines PlantBots

# spiffs-data.zip entpacken, dann im Ordner mit Updater/:
for f in Updater/*; do
  curl -sS -X POST "http://$IP/upload" \
    -F "upload_dir=Updater" \
    -F "upload_data=@$f"
  echo "  $f"
done
```

Danach z. B. `http://$IP/` und `/config` / `/modbus` hart neu laden. `config.json` bleibt erhalten.



### MQTT

**Status** `…/status` (schlanker):

- `online`, `ip_address`, `firmware_version`, `wifi_rssi`, `free_heap`, `uptime_seconds`, `watering`, `last_reset_reason`, `latest_version`, `update_needed` (**bool**)
- entfernt aus Status: `flow`, `last_volume_ml`, `water_runtime` (Live weiter über `…/logs`)

**Logs** `…/logs`:

- Top-Level: `job_id`, `type`, `phase`, `success`, `status`, optional `plant_id`
- nested `water` und/oder `fertilizer` je Phase:
  - `dose` / `flush` → nur `fertilizer` (falls Dünger)
  - `water` → nur `water`
  - `done` → `water` + ggf. `fertilizer`
- je Block u. a. Mengen, `flow`, `percent`; Wasser zusätzlich Pumpe/Ventil/Dauer

**ACK** unverändert für Server-Jobs (`job_id > 0`).

### Home Assistant / Server

- HA-Button-Pfad: `/restart` statt `/HA/reset`
- HA/Server: nested `water`/`fertilizer` in Logs (kein Fallback auf flache Felder); fehlende Blöcke in der UI aus vorherigem Live-Update mergen
- Empfohlen: HA-Integration nach Firmware-Update neu laden

## Upgrade-Checkliste

1. Firmware `v1.3.0-delta` per OTA (Beta-Schalter) oder USB flashen
2. SPIFFS **manuell** nachladen (curl oben) — Auto-UI-Update gilt erst für Updates *nach* Delta
3. `/config`: Tank nutzen / Tiefe / Mindestfüllstand prüfen; Pre-Releases aktiv lassen
4. Test: Startseite → Neustart (Display „Neustart…“)
5. Test: `/modbus` scannen und ggf. Adresse ändern
6. Test: Gießen mit/ohne Dünger — Logs nur mit passendem Block
7. MQTT `…/status`: `update_needed` als true/false; keine Flow/Volume-Felder mehr im Status
8. HA neu laden; Restart-Button und Live-Gießen prüfen

---



## Bekannte Hinweise

- SPIFFS-Auto-Update braucht Dateien **im Repo am Tag**; nur die Zip am Release ändert den Raw-Pfad nicht.
- Update auf Delta: Web-UI **manuell** (curl); Folgereleases: Auto-SPIFFS durch Delta-Firmware.
- Modbus-Scan blockiert den HTTP-Request einige Sekunden (Bus-Timeouts).
- Sticky Display-Meldungen (`time == 0`) bleiben bis zum Neustart oder einer bewussten Freigabe.
- Control-/Direktgießen ohne Server-`job_id` erzeugt weiter keine Job-Logs/ACKs.
